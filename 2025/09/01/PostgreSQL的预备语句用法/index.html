PostgreSQL的预备语句用法
梧杵 元婴问道
  2025-09-01 20:09:48   2025-09-01 20:38:13

  • 预备语句
  

一、什么是预备语句？

预备语句（Prepared Statement），有时也称为参数化语句（Parameterized Statement），是关系型数据库中的一个特性。它允许你将 SQL 语句的结构与它的参数值分开发送给数据库。

它通常遵循一个“准备-执行”的两步模型：

  1. 准备（Prepare）: 将带占位符的 SQL 模板发送到数据库服务器。数据库会解析（Parse）、检查语法和语义、并进行查询优化，生成一个执行计划。然后将这个编译好的语句存储起来，并返回一个句柄（如名称或 ID）。
  2. 执行（Execute）: 之后，你只需要将参数值和这个句柄发送给数据库服务器。服务器会将参数与之前编译好的模板结合，直接执行。

需要注意的是，预备语句只在当前连接存活期间有效，一旦连接关闭，它就会失效。详细原理见：https://mp.weixin.qq.com/s/Sulc6CB5OfT8j_zCNj1tIg

二、工作原理

没有预备语句的传统查询：
"SELECT * FROM users WHERE id = 123"
每次执行这条语句，数据库都需要完成：语法解析 -> 语义检查（表/列是否存在）-> 查询优化（选择最优执行计划）-> 执行。对于只是 id 值不同的重复查询，前三个步骤是完全冗余的，浪费资源。

使用预备语句的查询：

  1. 准备阶段：应用程序发送 "SELECT * FROM users WHERE id = $1"。
    • 数据库完成：解析 -> 语义检查 -> 查询优化。
    • 将编译好的计划存储，并命名为 user_query。
  2. 执行阶段：应用程序发送 EXECUTE user_query(123)。
    • 数据库跳过前三个步骤，直接使用 user_query 的计划，将参数 123 代入，然后执行。
  3. 后续执行只需发送 EXECUTE user_query(456)，EXECUTE user_query(789)，效率极高。

三、核心作用与优势

  1. 防止 SQL 注入（最重要作用）

    • 原因：因为 SQL 结构（代码）和参数值（数据）是分开发的。即使用户输入的参数值中包含恶意的 SQL 代码（如 ' OR '1'='1），数据库也会始终将其视为纯数据，而不会将其作为 SQL 代码的一部分来解析和执行。
    • 结论：这是防范 SQL 注入攻击的首选且最有效的方法，远比手动转义用户输入可靠。

  2. 提升性能（尤其适用于重复查询）

    • 原因：避免了多次解析和优化相同结构的 SQL 语句，只需一次准备，多次执行。对于在循环中执行的 INSERT、UPDATE 或高频 SELECT 查询，性能提升非常显著。

  3. 简化数据类型处理

    • 在准备阶段，参数的数据类型就已经确定了。应用程序在传递参数时，无需担心如何将字符串正确地转换为日期、数字等SQL数据类型，数据库驱动会自动处理转换。

四、在常用编程语言中的使用教程

在现代编程中，你很少会直接使用 PREPARE 和 EXECUTE 这样的原始 SQL 命令。绝大多数数据库驱动（如 JDBC, PDO, psycopg2 等）都提供了抽象的接口，它们底层会自动使用预备语句。

1. Python (使用psycopg2库连接PostgreSQL)

2. Java (使用JDBC连接数据库)

3. PHP (使用PDO扩展)

PDO (PHP Data Objects) 是 PHP 中数据库访问的推荐方式，它天然支持预备语句。

4. Node.js (使用node-postgres库)

总结

特性 传统语句 预备语句
安全性 低，易受 SQL 注入攻击 高，有效防止 SQL 注入
性能 每次都需要解析和优化 一次准备，多次执行，性能高
开发体验 需要手动处理数据类型和转义 驱动自动处理参数，更简单可靠
适用场景 一次性、动态复杂的查询 重复性高、结构固定的查询（如循环插入）

最佳实践： 除非是极其特殊的情况（如动态构建复杂的、不确定的 WHERE 子句），否则应始终使用参数化查询（预备语句）来执行所有涉及用户输入的 SQL 操作。这应被视为编写数据库操作代码的黄金准则。
