高可用从来不是一个功能，而是一整套哲学。
PostgreSQL 的流复制机制，把”主库写，备库跟“这件事做到了优雅、稳定、可调。本篇文章，我们从原理讲到架构，从配置讲到排障，全面梳理流复制的艺术。

🌊 什么是流复制？

PostgreSQL 的流复制（Streaming Replication），本质上是一件朴素的事：

Primary 把产生的 WAL 日志通过 TCP 连接持续发送给 Standby，Standby 不断重放这些 WAL，保持与主库一致。

一张图看清本质：WAL 是主备之间唯一的”血管”。

🧬 WAL 流的三种传输方式

1. 异步复制（默认）

Primary 不等备库确认，事务就算提交。

  • ✅ 主库延迟最低
  • ❌ 主库宕机时，可能丢失最近几条事务

2. 同步复制

Primary 等至少一个备库 fsync 落盘后，才算提交成功。

  • ✅ 强一致，RPO = 0
  • ❌ 备库挂了或网络抖动，主库写入会卡死

3. Quorum 同步（PG 10+）

只要 任意 2 个备库确认就提交——在一致性和可用性之间取巧妙平衡。

🔄 复制的四个关键 LSN

流复制中，每个阶段都有自己的 LSN 坐标：

  • write_lsn：备库已接收并写入 WAL 文件的位置
  • flush_lsn：备库已 fsync 到磁盘的位置
  • replay_lsn：备库已重放到数据页的位置

🧃 复制槽（Replication Slot）：不再”丢 WAL”

没有复制槽时，如果备库离线太久，主库可能已经回收了备库还没拉走的 WAL。再连上来就提示：

这就意味着需要重新做 basebackup。

复制槽的作用：

让主库知道“有个备库还没消费到这里”，禁止回收这部分 WAL。

注意：复制槽失活（备库长期离线）会让主库无限堆积 WAL，磁盘打爆。

🧠 备库的”热读”能力

hot_standby = on 让备库允许只读查询，但有一个微妙的问题：

Hot Standby 的查询冲突

备库正在重放一个清理死元组的 WAL，而此时有一个长查询正在读这些数据——怎么办？

PostgreSQL 的默认策略：取消查询。

解决方案

方案 1：推迟重放

给查询留一个宽限窗口。代价是备库延迟可能增加。

方案 2：同步快照（hot_standby_feedback）

备库主动告诉主库：”我这里还有 XID=xxx 的事务在跑”，主库就不清理对应的元组。
副作用：主库 VACUUM 效率可能下降。

选择哲学：读多慢查询 → 开 feedback；写优先 → 开 max_standby_delay。

🧭 延迟备库（Delayed Standby）

这是一个常被低估的功能——专门给”人类犯错”准备的后悔药：

备库接收 WAL 后延迟 1 小时再重放。
万一主库上误删了表，你还有 1 小时时间从这个备库救数据。

低成本、极高性价比——每个生产集群都应该配一个。

📡 逻辑复制 vs 物理流复制

顺带澄清一个概念：

物理流复制 逻辑复制
传输单元 WAL 字节流 解码后的行级变更
主备版本一致性 必须一致 可跨大版本
备库是否可写 只读 可写
粒度 整个集群 单表 / 单数据库
典型用途 高可用、读写分离 数据集成、跨版本升级、CDC

一句话：高可用用物理流复制，数据流动用逻辑复制。

🧯 常见故障与排查

症状 1：replay_lag 持续增长

可能原因：

  • 备库 I/O 或 CPU 饱和 → 监控备库负载
  • 主库生成 WAL 过快 → 关注批量写入
  • 备库配置过低 → 调大 max_wal_senders, wal_receiver_timeout

症状 2：主库 pg_wal 爆满

查复制槽：

有非活跃且保留大量 WAL 的槽 → 删掉或修复备库。

症状 3：备库日志出现 requested WAL segment has already been removed

主库 WAL 被回收了。解决：

  • 使用复制槽
  • 加大 wal_keep_size
  • 配置 WAL 归档（archive_command）+ restore_command

🏰 生产级高可用拓扑

  • 至少 1 个同步备库保 RPO
  • 多个异步备库承接只读流量
  • 1 个延迟备库做人祸后悔药
  • Patroni配合 etcd/Consul 做自动故障转移

✨ 结语

流复制是 PostgreSQL 最”稳重”的特性之一：

  • 简单得像一条水管
  • 灵活得像一件织物
  • 强大得像一座堡垒

它用 WAL 连接了时间与空间，让一份数据在多个节点同一频率跳动。

不是因为数据库强，才有高可用；而是因为有流复制，数据库才敢说”我永远在线”。
