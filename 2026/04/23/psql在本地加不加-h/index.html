这是一个很好的问题！psql 直接连接和加 -h 127.0.0.1 虽然都是连接本机，但有重要区别：

🔑 核心区别：连接方式不同

1. 直接连接（不加 -h）

使用：Unix Domain Socket（本地套接字）

  • 通过文件系统的 socket 文件连接
  • Socket 文件路径通常是：/var/run/postgresql/.s.PGSQL.5432 或 /tmp/.s.PGSQL.5432
  • 不经过网络栈，直接进程间通信（IPC）

2. 加 -h 127.0.0.1

使用：TCP/IP 网络连接

  • 通过 TCP 协议连接到 127.0.0.1:5432
  • 经过网络栈（即使是本地回环）
  • 需要监听 TCP 端口

📊 详细对比表

特性 不加 -h（Unix Socket） -h 127.0.0.1（TCP/IP）
连接方式 Unix Domain Socket TCP/IP 网络
性能 ⚡ 更快（少了网络开销） 🐢 稍慢（经过网络栈）
pg_hba.conf 配置 local 规则 host 规则
需要监听配置 不需要 需要 listen_addresses 包含 localhost
安全性 🔒 文件权限控制 🌐 网络层认证
跨主机 ❌ 不支持 ✅ 支持

🚨 常见问题排查

问题1：Unix Socket 连接失败

解决：

  • 检查 PostgreSQL 是否运行：pg_isready
  • 检查 socket 文件位置：SHOW unix_socket_directories;
  • 明确指定 socket 目录：psql -h /tmp -U postgres

📌 总结

使用场景 推荐方式 理由
本地管理维护 Unix Socket（不加 -h） 最快、最安全
应用开发测试 TCP/IP（-h 127.0.0.1） 与生产环境一致
自动化脚本 明确指定方式 避免环境差异
高安全要求 Unix Socket + peer 文件权限控制
需要网络监控 TCP/IP 便于网络层面的监控和分析

关键点： 虽然都是连接本机，但 Unix Socket 是文件通信，TCP/IP 是网络通信，两者在性能、安全性、配置要求上都有显著差异！
