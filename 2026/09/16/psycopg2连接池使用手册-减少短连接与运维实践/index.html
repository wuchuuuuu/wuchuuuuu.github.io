psycopg2 连接池使用手册：减少短连接与运维实践

一、背景与目标

在使用 psycopg2-binary==2.9.7 并启用连接池的场景下，连接池本身并不能完全消除短连接。psycopg2 的 pool 在归还连接时存在一个关键行为：当空闲池中已持有 minconn 个连接时，超出部分的连接会被物理关闭而非保留复用。在并发持续高于 minconn 的情况下，minconn 与 maxconn 之间的连接会不断经历“新建—使用—关闭”的过程，从数据库侧观察即表现为短连接抖动。

本手册用于规范连接池的配置与使用方式，并从运维角度给出连接数规划、参数防护和监控告警建议，目标是使数据库连接稳定复用、消除非预期的短连接。

  • 初始化时开启 minconn 个连接，并发升高时按需新建，上限为 maxconn。
  • 连接归还时，只要空闲池中已存在 minconn 个连接，超出的连接即被关闭。
  • 因此当并发持续高于 minconn 时，minconn 至 maxconn 区间的连接会反复开启和关闭，形成短连接。

三、配置规范

3.1 核心原则

  1. 将 minconn 与 maxconn 设为相同值，使归还的连接不会被关闭，全部长期复用。
  2. 借用与归还必须成对出现，并通过 try/finally 保证异常路径也能归还；禁止对池中借出的连接直接调用 close()。
  3. 连接池以进程为单位保持单例，不在每次请求时新建连接池。
  4. psycopg2 连接池不自带空闲超时与保活机制，需在应用层补充探活，或在架构层前置 PgBouncer。

3.2 连接池初始化

在多进程部署（gunicorn、uwsgi）下，连接不能跨 fork 共用，必须在每个 worker 内各自初始化连接池，通常放在 post_fork 钩子中完成。

五、保活与连接回收

psycopg2 连接池不提供 pool_recycle 与预探活（pre-ping）能力，需通过以下两种方式之一补齐。

六、运维建议

6.1 连接数规划

  • 总连接需求约等于「每进程 maxconn 数 × 进程（worker）数」，该值必须低于 PostgreSQL 的 max_connections 并预留余量。
  • 每进程 maxconn 的取值可从「该进程峰值并发 SQL 数」起步，并非越大越好。连接数过多会增加 PostgreSQL 的上下文切换开销与内存占用（每连接受 work_mem 影响）。
  • 需为 DBA 操作、监控采集、备份任务预留连接。建议 max_connections 的实际使用率不超过 80%。

6.2 数据库侧防护参数

  • idle_in_transaction_session_timeout：防止应用未及时结束事务导致连接长期停留在 idle in transaction 状态，这是拖垮实例的常见原因。
  • 客户端 keepalives 与服务端 tcp_keepalives_*：防止 NAT 或负载均衡静默断链后，应用继续使用已失效的连接。
  • statement_timeout：作为兜底，避免慢查询长期占用连接。

6.3 监控与告警

按连接状态与来源统计当前会话：

  • 短连接判定：监控连接建立速率（每秒新建连接数）或 pg_stat_database.numbackends 的抖动。若新建速率高而 numbackends 相对平稳，说明存在连接反复开启与关闭。
  • 建议告警项：连接数接近 max_connections；idle in transaction 会话数量或持续时长超过阈值；连接建立速率突增。
  • 为每个服务设置 application_name，便于在 pg_stat_activity 中按来源定位问题。

6.4 上线与高可用

  • 上线前进行压测，确认高并发下 PostgreSQL 侧连接数稳定在 minconn（等于 maxconn）附近，且无明显的新建与关闭抖动，方可判定连接池配置正确。
  • 主从切换或实例重启后，池中原有连接全部失效。必须配合应用层探活或 PgBouncer，否则切换瞬间应用会集中获取到失效连接并报错。

七、要点小结

  • 将 minconn 与 maxconn 设为相等，并严格执行 getconn 与 putconn 成对使用，是消除短连接、实现长连接复用的前提。
  • 数据库侧配置 idle_in_transaction_session_timeout 与 keepalives，防止连接卡死与失效。
  • 监控重点关注连接建立速率与 idle in transaction 状态，连接数规划预留约 20% 余量。
  • 连接规模较大时，引入 PgBouncer 进行连接收敛与统一管理。
